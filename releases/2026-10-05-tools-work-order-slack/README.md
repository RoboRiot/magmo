## Scope

- Work Order Add distinguishes tool IDs (`AIS_T#####`) from ordinary item IDs and storage IDs. Tool movements preserve the previous configuration/history and current work-order selection.
- Scanned bins and pallets produce compact Slack targets rather than a separate Slack row for every contained inventory item. Inventory movement and containment remain separate from Slack presentation.
- Both tool-page Slack submission and Work Order Add use one authenticated, tool-ID-based guard. It checks active and archived Slack rows and reports an existing tool without creating another row or work-order thread link. Transactional receipts prevent concurrent Magmo requests from blindly creating duplicates; incomplete deliveries reuse the saved payload and row.
- A failed/ambiguous Slack lookup or uncertain create fails closed. Slack does not provide a unique-ID constraint, so a human or unrelated application can still race to insert an independently created duplicate. This release does not claim control over those external writers.
- Tool pages have an authenticated Print Label action using persisted tool information. The printer receives a dedicated tool template, full tool-ID barcode and a tool-page QR code. Existing regular, bin and pallet label layouts are preserved.
- Firestore rules add exactly two exclusions that block browser access to server-only `ToolSlackDeliveries` receipts. No inventory migration or database rewrite is part of deployment.
